### App Transport Security（ATS）[实测]

```xml
NSAllowsArbitraryLoads = false            ← 全局禁止明文 HTTP
NSAllowsArbitraryLoadsInWebContent = true ← 2026-10-01 新增：仅豁免 WKWebView 网页内容 ATS
                                            （外链 PC 站如图书馆 sslibrary.com 为明文 HTTP；
                                             App 主网络层 URLSession 仍严格 ATS）
NSExceptionDomains:
  sxjzit.edu.cn:
    NSExceptionAllowsInsecureHTTPLoads = true   ← 但对该校域名放行 HTTP
    NSIncludesSubdomains = true
```

> ⚠️ 这是「隐私文本宣称全 HTTPS」与实现之间的**已知矛盾点**之一（见 [01-项目整体架构](01-项目整体架构.md) §1.10）：学校部分图床/接口仍为 HTTP，故对 `*.sxjzit.edu.cn` 单独放行明文加载；`NSAllowsArbitraryLoadsInWebContent` 是 Apple 官方推荐的「只放开 Web 内容」键，不宽限 App 自身的网络栈。

### Entitlements [实测]

**文件内容**：仅一项能力 `com.apple.developer.associated-domains` = `applinks:$(WECHAT_UL_HOST)`（即 `applinks:jl.43322.cn`）。

> 🔴 **重要缺陷（本轮实测修正）**：`project.pbxproj` 中 **`CODE_SIGN_ENTITLEMENTS` 出现 0 次**。`DesignCode.entitlements` 仅作为一条 `PBXFileReference`（L139）与一条 group 成员（L247）存在，**从未绑定到任何 target 的构建设置**，因此：
> - **Associated Domains 能力实际上没有被签名进 App**；
> - 微信 **Universal Link 回跳链路断链**（URL Scheme 回跳仍可用，见 Info.plist 的 `CFBundleURLTypes`）。
>
> 修复方式：在主 target 的 Debug/Release 构建设置中加入 `CODE_SIGN_ENTITLEMENTS = DesignCode/DesignCode.entitlements`，并在 Apple Developer 后台为 App ID 开启 Associated Domains。

文件内注释（L4-12）要求：域名必须与「微信开放平台 → 应用详情 → Universal Link」及服务端 AASA 文件（`https://<域名>/.well-known/apple-app-site-association`）**完全一致**；只需改构建设置 `WECHAT_UL_HOST`，本文件自动替换。相关文件见 `qin/docs/wechat-integration/well-known/`。

## 5.4 构建

### 真机构建（项目约定方式）

```bash
# 在仓库根目录执行
xcodebuild \
  -project qin/DesignCode.xcodeproj \
  -scheme DesignCode \
  -configuration Debug \
  -destination "platform=iOS,id=00008110-000411A40EC1401E" \
  -derivedDataPath qin/build/device-dd \
  -allowProvisioningUpdates \
  build
```

产物：`qin/build/device-dd/Build/Products/Debug-iphoneos/DesignCode.app`

> 若签名失败，提示为：确认 `DEVELOPMENT_TEAM=F2JL9GNLCC` 下自动签名可用（用 Xcode 打开工程一次即可刷新描述文件）。构建日志落在 `qin/build/verify/device_build_<时间戳>.log`。

### Release 构建

```bash
xcodebuild -project qin/DesignCode.xcodeproj -scheme DesignCode \
  -configuration Release -destination "generic/platform=iOS" \
  -derivedDataPath qin/build/Build build
```

### 模拟器构建（仅供验证编译）

```bash
xcodebuild -project qin/DesignCode.xcodeproj -scheme DesignCode \
  -configuration Debug \
  -destination "platform=iOS Simulator,name=iPhone 17 Pro" \
  build
```

> 模拟器不能验证 Face ID、微信回跳、真机渲染差异。**不要用模拟器结论替代真机验收。**

### Xcode GUI 方式

1. 打开 `qin/DesignCode.xcodeproj`
2. 顶部 Scheme 选 `DesignCode`，目标设备选「秦超的iPhone」
3. `⌘R` 运行；`⌘U` 跑测试

## 5.7 设备安装与调试（devicectl）

```bash
# 列出设备（确认 UDID 与连接状态）

  --device 00008110-000411A40EC1401E \

# 启动 App（先终止已有进程）
xcrun devicectl device process launch \
  --device 00008110-000411A40EC1401E \
  --terminate-existing com.qinchao

xcrun devicectl device process launch \
  --device 00008110-000411A40EC1401E \
```

## 5.11 排障

| 症状 | 排查方向 |
|---|---|
| 构建失败且报「显示设置覆盖护栏」 | 排版写法违反四规则。按 `display_coverage_guard.py` 输出定位；确需豁免则加 `display_coverage_allowlist.txt` |
| 构建报 `python3: command not found` | 护栏脚本依赖 `python3`，需确保在 `PATH` 中 |
| 签名失败 | 确认 `DEVELOPMENT_TEAM=F2JL9GNLCC` 自动签名可用；用 Xcode 打开工程刷新描述文件 |
| `devicectl` 报设备 `unavailable` | 真机未连接/未解锁/未信任。当前本机实测即为 `unavailable`，需先连接设备 |
| 脚本预检失败 | 设备必须 connected；确认 UDID 未被 `--device` 覆盖错 |
| 单元测试挂 | 先判断是否为**在线测试**受学校数据漂移影响（见 §5.5 脆弱性提示） |
| 找不到 scheme | 仓库未提交共享 scheme，先用 Xcode 打开工程一次以自动生成 |
| 模拟器跑不出效果 | 属预期。Face ID / 微信回跳 / 真机渲染必须真机验证 |
