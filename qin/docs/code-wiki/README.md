## 一页速览

- 是什么：山西晋中理工学院校园信息聚合 iOS App，纯 SwiftUI，唯一第三方为微信开放平台 SDK（2026-09-27 接入），无后端、无账号体系。
- 数据从哪来：学校公开 API `https://gwqietap.sxjzit.edu.cn/mapi`（GET 只读）+ 开发者博客 `https://www.43322.cn/blog`（公告/隐私协议），失败时降级本地 JSON 缓存 → 静态兜底数据。
- 最核心的特色：无服务端条件下，用官网指纹轮询自建了一套本属于服务端的本地推送体系（新闻/信箱/概况/党建四通道 + 收藏第五通道）与站内信消息中心；并以 `URLProtocol` 埋点自建全 App 网络遥测（链路/吞吐/延迟/诊断/测速）。
- 规模（2026-09-28 `wc -l` 实测）：48 个 Swift 源文件共 60,939 行——主 target 46 文件 58,478 行 + 测试 3 文件 2,461 行；主视图集全在单文件 [TabBar.swift](file:///Users/qinchao/Downloads/designcode-swiftui/qin/DesignCode/TabBar.swift)（12,755 行，60+ View）。单元测试 133 例（MessageCenterStore 系 88 + NetworkServiceDTO 系 22 + WeChatSDK 系 23）；2026-09-28 真机复测 133/133 通过（0 失败，日志 `qin/build/verify/longimage_black4_test.log`）。
- 日志：自研 `LogManager`，全工程 38 个日志域、1,119 处字面域埋点（`LogManager.shared` 调用点共 1,155 处），可在「我的 → 应用日志」查看；网络监测独占 `netmon` 域 47 处、显示设置独占 `display` 域 40 处、微信集成独占 `wechat` 域 65 处、长图生成独占 `longimage` 域 48 处。
- 构建环境：Xcode 27.0（27A266a）+ iOS 26 SDK；真机「秦超的iPhone」（iPhone 13 Pro Max，UDID `00008110-000411A40EC1401E`）为唯一调试目标。

## 设计目标与约束

设计目标（逆向归纳）：校园信息在单一入口可达；无服务端也能完成更新触达；弱网与断网下仍可阅读；锁定隐私内容；视觉与交互达到可评审的完成度；全部行为可观测、可审计。

硬约束（这些约束解释了文中的多数设计取舍）：

| 约束 | 来源与影响 | 标注 |
|---|---|---|
| 无自建服务端、无推送服务端 | 推送必须改由客户端轮询 + 本地指纹比对实现 | [Data-backed] |
| 无账号体系 | 无登录态，全部内容公开；消息中心即唯一站内信形态 | [Data-backed] |
| 学校 API 仅 GET、无版本号 | 客户端只能容错解码，不做协议协商 | [Data-backed] |
| 第三方依赖极少 | 图片加载、遥测、日志、字体下载均自研或直用系统框架；唯一第三方为微信开放平台 SDK（官方 XCFramework，仅用于分享/登录/小程序） | [Data-backed] |
| 真实设备为唯一调试目标 | 模拟器结果不作为验收依据（ProMotion、Keychain、字体下载均在真机验证） | [Data-backed] |
| 仓库无有效 git | 改动前必须手动备份，回滚依赖备份目录 | [Data-backed] |

## 证据标注体系

各分册对设计取舍与约束使用四类标注，便于评审区分事实与推断：

| 标注 | 含义 | 在本文档中的典型对象 |
|---|---|---|
| `[Data-backed]` | 可由源码或实测数据直接复核 | 行号、常量、埋点计数、配置项 |
| `[Research-backed]` | 依据公开规范或平台文档 | WCAG 对比度阈值、ImageIO 降采样、CTFont 下载 API 行为 |
| `[Expert judgment]` | 基于工程经验的判断，未独立验证 | 架构风格取舍、模块边界、迁移策略 |
| `[Hypothesis]` | 为填补信息缺口所做的假定，须确认 | 逆向归纳的产品意图、未来规模假设 |

凡未标注的源码事实陈述（行号、类型名、常量、计数）均为 `[Data-backed]`，不再逐句重复标注。

## 术语表

| 术语 | 含义 |
|---|---|
| 通道 | 推送/站内信的消息来源分类：新闻、信箱、概况、党建、收藏更新 |
| 基线（Baseline） | 轮询比对用的指纹快照（如 `schoolProfileBaseline` 的三段计数），变化即触发通知 |
| 深链（DeepLink） | 由通知或消息中心发起的页面跳转载荷；统一经 `pendingDeepLink` 状态投递 |
| 降级（Degradation） | 数据获取失败时按「API → 本地缓存 → 静态兜底」逐层回退 |
| 台账（Ledger） | netmon 的线程安全请求记账槽，记录在飞请求、字节与延迟 |
| presentation | SwiftUI 的 sheet / fullScreenCover 弹出层；不继承父级视图修饰器（灰度因此需单独挂载） |
| 灰度模式 | 全局去饱和的专注阅读模式（`.saturation(0)`），覆盖主层级与全部内容级弹出层 |
| 排版方案 | 一键套用六项排版值（字号档/行距/字距/粗体/系统字体/字体家族）的预设 |
| 纸面预览 | 文章文字颜色的白纸/深纸双环境模拟预览，配合 WCAG 对比度自检 |
| 静默检查 | 仅写入站内信、不触发系统通知的轮询模式（消息中心前台自动检查用） |
| 防轰炸 | 单次轮询最多推送 5 条、间隔 1 秒的节流策略 |
| 幂等 | 重复操作不改变状态（如已读消息再次点「已读」）；有效方向的操作必须有完整动效 |
| 回执 | 通知回调中的 `completionHandler` 立即返回，业务处理转入主线程任务 |
| 代际（cacheGeneration） | 手动刷新时递增的版本号，用于丢弃在途的旧缓存写回 |
